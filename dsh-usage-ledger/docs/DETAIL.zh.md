## 回填语义（禁用 / 重装 / 升级）

- **延迟的存活会话**：回填扫描到达时仍存活（窗口未关）且尚未记录存活边界的会话会被**延迟**——暂不写入游标，待其关闭后由后续扫描全量回放。状态在 `/status` → `backfill.deferredSessions` 中展示。
- **离线窗口补洞**：插件被禁用、卸载或升级期间持久化的事件，会在下次激活时补回（存活链路首次观测到的位置与会话行 `lastSeq` 高水位对比，差额从日志回放）。事实按幂等 upsert 写入，过时的高水位至多导致重复回放，绝不重复计数。
- **启动期对账 sweep**：主历史扫描结束后，每个游标已标记且当前不存活的会话都会与会话行的 `lastSeq` 高水位对账。完全没有行（旧版零标记 bug 的受害者）→ 从 seq 0 全量回放整条日志；行高水位低于日志最大 seq（插件完全离线期间持续持久化事件、随后关闭的会话）→ 回放高水位之后的开放尾部；否则该会话已记账，仅产生一次只读日志扫描。存活会话与延迟会话一律不碰——它们归存活链路所有。对账结果在 `/status` → `backfill.sweep`（`{checked, replayed}`）中报告；`/usage-ledger/api/reset`（清空 + 全量重扫）仍可作为手动兜底手段。
- **继承前缀回放**：回放无条件跳过宿主报告的 `inheritedEventCount` 切点之前的前缀。宿主保证该切点大于 0 当且仅当会话是 seeded——包括 UI fork 出的、header 里没有 parentSession 的 seeded 子会话；未 seed 会话的切点恒为 0，跳过对它是空操作，其整条日志（完整的正史）天然全量回放。seeded 子会话被跳过的前缀归其父会话自己的回放所有（实测一个 seeded 子会话与父会话日志重叠约 6.3M token），跳过正是为了防止跨会话重复计数。
